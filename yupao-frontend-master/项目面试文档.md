# 伙伴匹配中心项目 - 面试文档

## 一、项目概述

### 1.1 项目背景
伙伴匹配中心是一个基于标签匹配的社交平台，帮助用户找到志同道合的伙伴，组建团队进行学习、竞赛或项目合作。

### 1.2 核心功能
- 用户注册登录
- 用户标签管理
- 基于标签的智能匹配（编辑距离算法）
- 队伍创建、加入、退出
- 队伍搜索和筛选
- 用户信息管理

### 1.3 技术亮点
- 使用编辑距离算法实现标签相似度匹配
- Redis缓存优化推荐系统性能
- Redisson分布式锁解决并发问题
- MyBatis-Plus实现CRUD操作
- Session+Redis实现分布式会话管理

## 四、核心功能实现

### 4.1 用户匹配算法

#### 算法原理
使用**编辑距离算法**（Levenshtein Distance）计算两个标签列表的相似度。

编辑距离是指将一个字符串转换成另一个字符串所需的最少单字符编辑操作次数（插入、删除、替换）。

#### 代码实现
```java
public static int minDistance(List<String> tagList1, List<String> tagList2) {
    int n = tagList1.size();
    int m = tagList2.size();

    if (n * m == 0) {
        return n + m;
    }

    int[][] d = new int[n + 1][m + 1];
    for (int i = 0; i < n + 1; i++) {
        d[i][0] = i;
    }

    for (int j = 0; j < m + 1; j++) {
        d[0][j] = j;
    }

    for (int i = 1; i < n + 1; i++) {
        for (int j = 1; j < m + 1; j++) {
            int left = d[i - 1][j] + 1;
            int down = d[i][j - 1] + 1;
            int left_down = d[i - 1][j - 1];
            if (!Objects.equals(tagList1.get(i - 1), tagList2.get(j - 1))) {
                left_down += 1;
            }
            d[i][j] = Math.min(left, Math.min(down, left_down));
        }
    }
    return d[n][m];
}
```

#### 匹配流程
1. 获取当前用户的标签列表
2. 查询所有用户
3. 计算当前用户与每个用户的标签编辑距离
4. 按编辑距离从小到大排序
5. 返回最匹配的N个用户

### 4.2 Redis缓存优化

#### 缓存策略
使用Redis缓存用户推荐列表，减少数据库查询压力。

```java
@GetMapping("/recommend")
public BaseResponse<Page<User>> recommendUsers(long pageSize, long pageNum, HttpServletRequest request) {
    User loginUser = userService.getLoginUser(request);
    String redisKey = String.format("yupao:user:recommend:%s", loginUser.getId());
    ValueOperations<String, Object> valueOperations = redisTemplate.opsForValue();
    
    // 读取缓存
    Page<User> userPage = (Page<User>) valueOperations.get(redisKey);
    if (userPage != null) {
        return ResultUtils.success(userPage);
    }
    
    // 查询数据库
    QueryWrapper<User> queryWrapper = new QueryWrapper<>();
    userPage = userService.page(new Page<>(pageNum, pageSize), queryWrapper);
    
    // 写入缓存
    try {
        valueOperations.set(redisKey, userPage, 30000, TimeUnit.MILLISECONDS);
    } catch (Exception e) {
        log.error("redis set key error", e);
    }
    return ResultUtils.success(userPage);
}
```

### 4.3 分布式锁

#### 使用场景
在用户加入队伍时，使用Redisson分布式锁防止超员问题。

```java
RLock lock = redissonClient.getLock("yupao:join_team");
try {
    // 尝试获取锁，最多等待3秒，锁自动释放时间10秒
    boolean isLocked = lock.tryLock(3, 10, TimeUnit.SECONDS);
    if (isLocked) {
        // 执行加入队伍逻辑
    }
} catch (InterruptedException e) {
    log.error("获取锁失败", e);
} finally {
    if (lock.isHeldByCurrentThread()) {
        lock.unlock();
    }
}
```

## 六、技术难点与解决方案

### 6.1 并发超员问题
**问题**：多个用户同时加入队伍，可能导致队伍人数超过限制。

**解决方案**：
- 使用Redisson分布式锁
- 在加入队伍前获取锁
- 执行加入逻辑后释放锁

### 6.2 推荐性能优化
**问题**：每次推荐都需要查询所有用户，计算编辑距离，性能较差。

**解决方案**：
- 使用Redis缓存推荐结果
- 设置合理的过期时间（30秒）
- 定时任务预热缓存

### 6.3 标签匹配准确性
**问题**：简单的标签匹配可能不够准确。

**解决方案**：
- 使用编辑距离算法计算相似度
- 支持多标签组合匹配
- 按相似度排序返回结果

### 6.4 会话共享
**问题**：多服务器部署时，Session无法共享。

**解决方案**：
- 使用Spring Session + Redis
- 将Session存储在Redis中
- 实现分布式会话管理

## 七、面试常见问题

### 7.1 项目介绍
**Q：请介绍一下这个项目**

A：这是一个基于标签匹配的伙伴匹配平台，帮助用户找到志同道合的伙伴。前端使用Vue3 + Vite + TypeScript，后端使用Spring Boot + MyBatis-Plus，数据库使用MySQL，缓存使用Redis。核心功能包括用户管理、标签匹配、队伍管理等。我负责了用户匹配算法的实现，使用编辑距离算法计算标签相似度，并使用Redis缓存优化性能。

### 7.2 技术选型
**Q：为什么选择Vue3而不是Vue2？**

A：Vue3相比Vue2有以下优势：
- 性能更好，使用Proxy替代Object.defineProperty
- Composition API提供更好的代码组织和复用
- 更好的TypeScript支持
- 更小的包体积

**Q：为什么使用MyBatis-Plus而不是JPA？**

A：MyBatis-Plus提供了：
- 强大的CRUD操作，无需编写XML
- 灵活的SQL编写能力
- 分页插件、代码生成器等实用功能
- 更好的SQL性能控制

### 7.3 算法问题
**Q：编辑距离算法的时间复杂度是多少？**

A：编辑距离算法的时间复杂度是O(m×n)，其中m和n分别是两个字符串（或标签列表）的长度。空间复杂度也是O(m×n)。

**Q：如何优化编辑距离算法？**

A：可以通过以下方式优化：
- 使用滚动数组将空间复杂度优化到O(min(m,n))
- 对于长标签列表，可以先进行预处理
- 使用缓存存储已计算的结果

### 7.4 并发问题
**Q：如何解决并发超员问题？**

A：使用Redisson分布式锁，在加入队伍时获取锁，确保同一时间只有一个用户能执行加入逻辑。锁的获取使用tryLock方法，设置合理的等待时间和锁自动释放时间，避免死锁。

**Q：分布式锁的实现原理是什么？**

A：Redisson基于Redis的SET NX EX命令实现分布式锁，支持：
- 可重入锁
- 公平锁
- 读写锁
- 联锁
- 红锁

### 7.5 缓存问题
**Q：如何保证缓存和数据库的一致性？**

A：本项目采用简单的Cache-Aside模式：
- 读取时先查缓存，缓存没有再查数据库
- 写入时先更新数据库，再删除缓存
- 设置合理的过期时间

**Q：缓存穿透、缓存击穿、缓存雪崩如何解决？**

A：
- 缓存穿透：对不存在的key也缓存空值，使用布隆过滤器
- 缓存击穿：使用互斥锁或热点数据永不过期
- 缓存雪崩：设置不同的过期时间，使用Redis集群

### 7.6 性能优化
**Q：项目做了哪些性能优化？**

A：
1. 前端：
   - 使用Vite构建工具，提升开发体验
   - 组件懒加载，减少首屏加载时间
   - 使用CDN加速静态资源

2. 后端：
   - Redis缓存推荐结果
   - 索引优化数据库查询
   - 分页查询减少数据传输量
   - 异步处理耗时操作

### 7.7 安全问题
**Q：如何保证用户密码安全？**

A：
1. 使用MD5+盐值加密存储密码
2. 前端传输使用HTTPS
3. 密码长度和复杂度校验
4. 定期提醒用户修改密码

**Q：如何防止SQL注入？**

A：
1. 使用MyBatis-Plus的参数化查询
2. 避免使用字符串拼接SQL
3. 对用户输入进行校验和过滤

### 7.8 项目难点
**Q：项目中遇到的最大难点是什么？如何解决的？**

A：最大的难点是实现用户匹配算法。最初使用简单的标签匹配，效果不理想。后来研究了编辑距离算法，实现了基于标签相似度的智能匹配。为了提升性能，还引入了Redis缓存。整个过程让我深入理解了算法在实际项目中的应用。
